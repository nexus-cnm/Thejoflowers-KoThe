# Thejoflowers-KoThe App Flow

## Onboarding and Sign-In/Sign-Up
When a new user first visits the application, they land on a simple public landing page that offers options to sign in or register. Choosing to register takes the user to a registration screen where they enter their name, email address, and password along with password confirmation. Upon submitting the registration form, the system validates the input and, if everything is correct, creates a new account and logs the user in automatically, redirecting them to the main dashboard. If the email address is already in use or passwords do not match, the user sees clear error messages above the related form fields. For existing users, the sign-in link opens the login form where they provide their email and password. Invalid credentials show an inline validation message without a page reload, thanks to Inertia.js. A “Forgot Password” link on the login page leads to a password recovery screen. There, users supply their email address and receive a reset link. Clicking that link brings them to a secure reset form where they set a new password. Once the new password is accepted, they are returned to the login page to access their account. Sign-out is available from a dropdown in the top navigation. Selecting it logs the user out immediately and returns them to the public landing page.

## Main Dashboard or Home Page
After signing in, the user arrives at the home screen, which serves as the application’s central hub. The header across the top displays the app name and the user’s avatar or initials alongside a dropdown menu for account settings and sign-out. Along the left side, a collapsible sidebar presents navigation links for Home and Tasks. The main content area greets the user with a welcome message and brief summary of their task count. The home page does not require any additional data loading; it simply sits ready as a jumping-off point. From this view, the user can click on “Tasks” in the sidebar, use the top navigation to reach account settings, or log out using the dropdown.

## Detailed Feature Flows and Page Transitions
When the user clicks “Tasks” in the sidebar, Inertia intercepts the link and sends an AJAX request to the backend. The server fetches the user’s tasks from the database, paginates them, and returns the data along with the Tasks Index component. The user sees a table of all tasks with columns for title, creation date, and action buttons. To create a new task, the user clicks the “New Task” button above the table. This triggers another Inertia request and brings up a task creation form. The form includes fields for title and description. Upon submitting, the backend validates the entries, creates the new task record, and issues a flash message indicating success. The UI automatically returns to the task list with the new entry visible. Editing a task works similarly: clicking an edit icon next to a task row loads an edit form pre-populated with the task’s existing data. Changes are sent back to the server, validated, and saved. A confirmation message appears at the top of the list, and the user sees the updated task immediately. Deleting a task is triggered by a delete icon; once confirmed in a JavaScript prompt, the request deletes the record and reloads the list with a success or error notification. Throughout these flows, all page transitions occur seamlessly through Inertia, updating only the parts of the page that change.

## Settings and Account Management
Account settings are accessed through the user dropdown in the header. Selecting “Profile” loads a settings page where the user can update their name and email address. A separate section on that page allows the user to change their password by entering their current password and a new password twice for confirmation. Each update triggers server-side validation. If there are validation errors, the fields in question display inline messages and preserve other inputs. Upon successful updates, the user sees a flash message and remains on the profile page. From here, the user can navigate back to the home dashboard or tasks list using the sidebar. The settings experience is fully integrated into the SPA, so no full-page reloads occur.

## Error States and Alternate Paths
If a user submits any form with invalid data, such as a blank task title or a password with insufficient length, the server returns validation errors. Inertia passes these errors back, and they appear directly under the relevant input fields. Attempting to access any protected route without being signed in causes an automatic redirect to the login page with a message explaining that authentication is required. In case of network issues during an Inertia request, the user sees a generic error banner indicating connectivity problems and can retry the action. If a password reset token is invalid or has expired, the user receives a clear message on the reset form page prompting them to request a new link. Any unexpected server error renders a simple error page with a request to reload or contact support.

## Conclusion and Overall App Journey
A typical user journey begins at the landing page, where someone either registers by providing their details or logs in with existing credentials. Once authenticated, they land on a welcoming home dashboard from which they manage tasks and adjust account settings. Creating, editing, and deleting tasks happen via smooth Inertia-driven page transitions that avoid full reloads and keep the interface responsive. Profile updates and password changes are handled in a similar fluid way. Error handling ensures validation feedback is clear and that users are never left wondering why a form submission failed. From start to finish, the application delivers a coherent SPA experience that covers all key flows without breaking user focus.
